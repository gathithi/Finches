## First, the domain question

I checked both:

```
deterpro.co.ke              -> DNS name does not exist
deterproenterprises.co.ke   -> DNS name does not exist
```

Neither is registered. DNS is working fine from here — `google.com`, `safaricom.co.ke` and `kenic.or.ke` all resolve — so this is specific to your domains.

**This does not block deployment.** Netlify gives every site a free address like `finches.netlify.app` with HTTPS included. Deploy today on that, register a domain when you're ready, and attach it later without redeploying.

It does mean **`info@deterpro.co.ke` is not receiving mail** — no domain, no MX records, so anything sent there bounces. That address is on your packaging and on every page of the site. Worth sorting regardless of the website.

Of the two names, `deterproenterprises.co.ke` is more descriptive but longer to type and to say over the phone. `deterpro.co.ke` is what your existing materials already print. I'd register **deterpro.co.ke** and point the longer one at it later if you want both.

## The folder structure

```
finches-site/
  public/            <- everything Netlify publishes
    index.html, products.html, ... 15 pages
    products/        6 product pages
    assets/          css, js, images
    robots.txt, sitemap.xml
  originals/         your source photos - never published
  build-*.ps1        page generators - never published
  crop-images.ps1    image tool - never published
  netlify.toml       config - read by Netlify, never served
  README.md, STILL-NEEDED.md, ... internal notes - never published
```

**This structure matters.** Before I split it, the whole folder was the publish root, which meant `STILL-NEEDED.md` — your internal list of missing dilution ratios and pending client permissions — would have been readable at `deterpro.co.ke/STILL-NEEDED.md`. So would the build scripts. `netlify.toml` now sets `publish = "public"`, so only the site ships. I verified this locally: all 10 site paths serve, all 8 private paths do not.

## Deploy method

### Drag and drop — start here

1. Go to **app.netlify.com** and sign in (GitHub, Google or email).
2. On the **Sites** page, drag the **whole `finches-site` folder** onto the drop zone.
   Not the `public` folder — the outer one. Netlify reads `netlify.toml` and publishes `public/` from it.
3. Wait about ten seconds. It goes live on a random address like `chipper-marzipan-4f1e9c.netlify.app`.
4. **Site configuration → Change site name** → set it to something like `finches` so the address becomes `finches.netlify.app`.

To update later: drag the folder again. Netlify keeps every previous deploy, so you can roll back with one click.

### Git — the upgrade, when you want it

Connecting a GitHub repo gives you version history, one-click rollback to any commit, and deploy previews.

**One thing to get right:** the pages are generated by PowerShell, and Netlify's build servers run Linux. They cannot run your build scripts. So commit the **already-built** `public/` folder and leave the build command **empty**. Netlify just serves what you committed.

## Settings

| Setting | Value |
|---|---|
| Build command | **leave empty** |
| Publish directory | `public` |
| Functions directory | leave empty |
| Node version | not applicable |
| Package manager | not applicable |

If you deploy by dragging the folder, `netlify.toml` sets the publish directory for you and there is nothing to type.

### Environment variables: **none**

You asked specifically, so to be clear: **this site needs zero environment variables.**

Environment variables exist to keep secrets out of your code — API keys, database passwords, tokens — and to feed them to a build process. This site has neither. It is static HTML, CSS and JavaScript with no build step, no server, no database, no third-party service and no authentication. There is nothing to keep secret.

Leave **Site configuration → Environment variables** completely empty. If someone tells you to add one, ask what it's for.

What would change that: adding a booking system, a payment gateway, a CMS, or anything that calls an API with a key. None of those are on the table.

### Other settings worth knowing

- **Asset optimization** (under Build & deploy): leave it **off**. It bundles and minifies CSS/JS, but yours is already lean and cache-versioned via `?v=N`. Turning it on adds a rewriting step that can fight your own cache strategy for no real gain.
- **Deploy notifications**: optional. Useful if you want an email when a deploy succeeds or fails.
- **HTTPS**: automatic, nothing to configure.
- **Compression**: automatic gzip and Brotli, nothing to configure.

## What `netlify.toml` already does

- Publishes only `public/`
- Caches `/assets/*` for a year (safe — the URLs carry `?v=N`, so a change to the CSS changes the URL)
- Tells browsers not to cache pages, so a price change appears immediately
- Sets `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options` and a restrictive `Permissions-Policy`
- Carries a commented-out HSTS block for later

## Attaching a domain, once you have one

1. **Site configuration → Domain management → Add a domain**
2. Enter the domain. Netlify shows the DNS records to create at your registrar.
3. At the registrar, add:
   - `A` record on the root (`@`) → the address Netlify shows (currently `75.2.60.5`)
   - `CNAME` record on `www` → `your-site.netlify.app`
4. Set the bare domain as **primary**. The site's canonical tags, `og:url` and all 14 sitemap entries already point at the bare domain, so making `www` primary would leave them contradicting the live site.
5. Wait for DNS, then Netlify issues a Let's Encrypt certificate on its own.
6. Once the certificate is active, turn on **Force HTTPS**.

Full detail, including the email risk if you ever move nameservers, is in `DOMAIN-SETUP.md`.

## Updating the site later

1. Edit the build scripts
2. Bump `$ASSETV` in `build-finches.ps1` if you changed CSS or JS
3. Run the three scripts in order
4. Drag the `finches-site` folder onto Netlify again

Every deploy is kept. If an update breaks something, **Deploys → pick the previous one → Publish deploy** puts it back instantly.
